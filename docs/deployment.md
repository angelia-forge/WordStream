# Deployment

## Deployment Contract

WordStream's SQLite deployment has four non-negotiable properties:

- one application instance and one Uvicorn worker;
- one persistent volume mounted at `/data`;
- `DATABASE_URL=sqlite:////data/wordstream.db`;
- `alembic upgrade head` runs from the container that can see that volume.

The image entrypoint applies migrations before starting Uvicorn. HTTPS is
terminated by Render or Fly.io.

Required production variables:

```text
ENVIRONMENT=production
AUTH_MODE=password
DATABASE_URL=sqlite:////data/wordstream.db
APP_TIMEZONE=Asia/Shanghai
APP_PASSWORD=<secret>
SECRET_KEY=<long-random-secret>
```

`APP_API_KEY` is optional. Generate secrets with a cryptographically secure
tool, for example `python -c 'import secrets; print(secrets.token_urlsafe(48))'`.

## Platform Comparison

| Concern | Render | Fly.io |
| --- | --- | --- |
| Repository config | `render.yaml` | `fly.toml.example` |
| Persistent disk | Service disk at `/data` | Named volume at `/data` |
| Instance policy | `numInstances: 1` | `min_machines_running = 1` |
| Region | Selected in dashboard | Explicit `primary_region` |
| HTTPS | Managed automatically | Managed automatically |
| Best fit | Simpler dashboard deployment | More infrastructure control |

Neither platform can horizontally scale this SQLite configuration.

## Render

1. Push the repository to a private or public Git provider.
2. In Render, create a Blueprint from `render.yaml`.
3. Enter `APP_PASSWORD` when prompted.
4. Confirm the disk is mounted at `/data` and the service has one instance.
5. Deploy and check `https://<service-host>/api/v1/health`.

`SECRET_KEY` is generated by the Blueprint. Do not regenerate it on routine
deployments because that invalidates existing sessions.

## Fly.io

Install and authenticate the Fly CLI, then:

```bash
cp fly.toml.example fly.toml
# Edit app and primary_region in fly.toml.
fly apps create <app-name>
fly volumes create wordstream_data --region <region> --size 1
fly secrets set \
  APP_PASSWORD='replace-me' \
  SECRET_KEY='replace-with-a-long-random-value'
fly deploy
fly status
curl --fail https://<app-name>.fly.dev/api/v1/health
```

Keep one Machine running. Do not add additional Machines sharing application
traffic with independent SQLite files.

## Backup

A plain `.db` copy is only valid after writes have stopped and the WAL has been
checkpointed. Use a maintenance window:

1. Stop the application writer or stop the service instance.
2. Mount the same `/data` volume in a maintenance container or shell.
3. Run `backup-sqlite /data/wordstream.db /data/backups`.
4. Copy the resulting timestamped file to storage outside the application
   volume.
5. Restart the service and check the health endpoint.

For a local Docker named volume, the stopped-writer procedure is:

```bash
docker stop wordstream
docker run --rm \
  -v wordstream-data:/data \
  --entrypoint backup-sqlite \
  wordstream /data/wordstream.db /data/backups
docker start wordstream
```

The script executes `PRAGMA wal_checkpoint(TRUNCATE)`, copies the database, and
runs `PRAGMA integrity_check` on the copy. Keeping backups only on the same
volume does not protect against volume loss.

## Restore

1. Stop all application writers.
2. Preserve the current database as a separate incident copy.
3. Replace `/data/wordstream.db` with the selected backup.
4. Remove stale `/data/wordstream.db-wal` and
   `/data/wordstream.db-shm` files.
5. Run `sqlite3 /data/wordstream.db 'PRAGMA integrity_check;'`.
6. Start the current image; its entrypoint upgrades the restored schema.
7. Verify `/api/v1/health`, login, vocabulary counts, and statistics.

Never restore while Uvicorn is running.

## Rollback

Application rollback means deploying the previous image only when its schema is
compatible with the current database. Alembic downgrades are not treated as a
production recovery guarantee. For incompatible schema changes, restore the
pre-deploy backup or deploy a forward fix.
